TRMNL recipe — Polling URL
==========================

Paste this as the plugin's Polling URL, with REPLACE_ME swapped for the
deployed Worker's hostname. It is one line; the breaks below are for reading
and must be removed.

TRMNL runs the Liquid on the left before fetching. Each card writes four
parameters: `cN` the station (`type:stopIds`, with an optional `!routes`),
`wN` the walk time, `nN` the title, `vN` the visibility toggle. A slot with
no station writes an empty `cN`, which the Worker skips.

They used to be packed into `cN` as `station:walk:title`. Do not go back:
the title is free text, so a colon in it was indistinguishable from a
separator, and a title that already held a packed slot gained another tail
on every round trip — typing a new title appended to the junk rather than
replacing it. `nN` is `url_encode`d so the encoder handles escaping.

The transit type is **not** written as part of the value: the picker stores it
on the front of the station already (`subway:127+725`), so adding
`{{ cardN_type }}` would produce "subway:subway:127+725" and shift every field
along by one. The Worker tolerates that doubled form, but the URL avoids it.

The `{% if cardN_station != blank %}` guard only skips a slot nobody has
configured, writing an empty parameter the Worker ignores. It deliberately
does **not** also test the visibility checkbox, which is passed through raw
as `vN` and decided on the Worker instead. Liquid is the wrong place for
that test: only `nil` and `false` are falsy there, so a checkbox arriving as
the *string* `"false"` is truthy and `{% if cardN_visible %}` hides nothing —
which is how the toggle shipped doing nothing at all. Which representation
TRMNL stores for an unticked box is undocumented, so `parseBoolean` in
`settings.ts` accepts every spelling and treats anything else as off.

A station value is stop IDs only, for every network. Values stored before
2026-11-01 may carry an `@<name>` suffix, which the Worker splits off and
discards — a bus card's heading now comes from NY Open Data rather than
from the stored value. Nothing here needs to handle either form.

Refresh rate
------------

15 minutes or slower. That is TRMNL's store minimum, and it is also why the
board shows clock times rather than a countdown: a "leave in 6 min" line is
stale by up to the refresh interval, while "16:12" never is.


A note on the station value
---------------------------

`cardN_station` holds what the picker stored, which already carries the
transit type and, for a bus corner, the stop name:

    subway:127+725+902+A27+R16
    bus:505507+505513@BORDEN AV/5 ST

`cardN_type` still drives the station picker (via `depends_on`) and decides
whether the slot is on at all, so it stays in the form — it just does not need
writing into the URL.
